01 / 背景

2000 个客户
名单
下一个该跟谁？

CONTEXT

一个普通客户经理手里挂着 1500–2500 个存量客户。每天工作的第一件事是打开 CRM，对着冗长的列表问自己一个问题：今天应该联系谁。

当时的解法是规则触发：到期未续、生日提醒、新产品上架，所有 trigger 进同一个收件箱。结果是：员工只看最上面 5 条，下面的全部跳过。系统上线半年，员工人均月联系客户数没动。

立项时我提了一句被印在 PPT 上的话："客户经理需要的不是更多触发，是一个排好顺序的清单。" 这一句是后面 11 个月所有取舍的锚点。

立项前的真实声音
"我每天打开 CRM 第一件事是关掉它。两千个客户挂在那不是帮忙，是焦虑。"
— 某支行客户经理 · 调研第 2 周
02 / 我做了什么

把推荐
拆成三层，
而不是一个分数.

APPROACH

所有人第一反应是「做一个客户优先级模型」。我们也这么做了。跑了三个月，准确率不错，但员工还是不点。复盘发现：一个分数解释不了「为什么这客户排第一」，也解释不了「我该跟他说什么」。

所以 V2 拆三层：分层（这客户值不值得跟）→ 匹配（跟他推什么）→ 时机（今天还是下周）。三层各跑各的模型，但在员工那里合成一句话："建议今天联系 X，推 Y，因为 Z 刚发生。"

L1
分层
~50w 客户
综合 AUM / 活跃 / 风险偏好 / 接触历史给每个客户打 0–1 分。Top 5% 进推荐池。
L2
匹配
300+ 产品
对客户 × 产品做二分类，输出含3 条人可读的匹配理由，员工对话时可以直接引用。
L3
时机
事件流模型
"今天"还是"下周"。基于行为序列预测最佳触达窗口。这一层是 +18pct 的关键。
→
输出
一句话
三层合成: "建议今天联系 张先生, 推 智能保 3 号, 他昨日的体检付费 触发风险类购买窗口。"
03 / 关键决策

三个让员工
真会用的
决定

KEY DECISIONS
01.
坚持「三句话推理」可解释
员工不会用一个黑盒。L2 输出必须附三条人可读的理由（最近行为 / 持仓结构 / 同类客户对照）。这让算法侧多出 25% 工作量，但员工接受度从 31% 跳到 64%。可解释是一个产品决定，不是合规要求。
+33pct 员工接受率
02.
把 L3「时机」从规则改成模型
V1 的 L3 是 "客户 30 天未联系 → 推荐"。粗糙但好理解。V2 改成事件驱动模型——客户做了哪些动作（理财赎回 / 大额转入 / 信用卡境外消费）会拉高今天联系的价值。这一层单独贡献了 +18pct 转化率。
+18pct 到访 / 联系转化
03.
推广先 KPI 后系统
试点单分行做完后，我没急着推。先用 3 个月时间和绩效团队对齐：客户经理打开率 / 完成率 进绩效。绩效一旦绑定，推广速度从「推不动」变成「分行抢着接」。从 1 家到 30+ 家分行只用了 5 个月。
30+ 分行 推广 5 个月内完成

这个项目最大的产出不是数字本身，是方法论：

—— 三层结构（分层 → 匹配 → 时机）后来成了部门做所有"AI 给一线"产品的默认拆法；

—— 「三句话可解释」这个具体动作被复用到 RAG 的引用展示和 Agent 的凭据链路上；

—— 「先 KPI 后系统」的推广路径，被组里其他两个产品延续——任何一个 AI 产品如果不进绩效，是推不动的。

06 / 反思

回看的话，
三件事我会改

LESSONS
01
V1 那三个月不应该跑「统一分数」。早就有信号说员工不接受黑盒，但我们坚持先把模型做强。其实三层结构 day 1 就有理论支撑，被「先简单后复杂」的工程直觉拖了 3 个月。
02
L3 时机层太晚才接 calendar。早期模型只看用户行为，不看员工档期。结果模型说"今天联系"，但员工在外面培训。「机器认知 ∩ 人工可执行性」是后来反复强调的产品边界。
03
没有给员工反馈通道。当时只看点击率，员工觉得推荐不准没地方说。后期补了「拒绝原因」一键反馈才好转——这个机制后来直接被 Agent 二期复用。反馈是产品的肌肉记忆。
